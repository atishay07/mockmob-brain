# UI standards digest (owner's; full rules and sources: wiki/concepts/ui-ux-standards.md)
For any UI/UX work, in any project, even when nobody asked for it. The project's own design system overrides these generic choices.
1. Brief first: the user's job, one primary action, which data is real, every state (loading, empty, error, sparse, success, return), and how you will prove it works.
2. Data decides the form. Units and denominators go beside counts; zero is not unknown; no false precision; real numbers only, each with context (trend, age or source).
3. The first thing seen answers the user's question. One dominant action, one information-carrying anchor, whitespace over boxes, never nested cards, nothing floating over content.
4. Type: one chosen family, few sizes, tight large headings, sentence-case labels (no ALL-CAPS eyebrows), tabular numerals (no monospace labels), 12-hour time.
5. Colour comes from meaning: one accent; no decorative gradients, glow or glass; neutral charcoal dark mode (not #000, not tinted); never colour alone; soft shadows.
6. Design every control state, focus included. Never show success before the system confirms it; no fake progress; errors give a way to recover.
7. Copy is plain and concrete: no hype, AI cliches, exclamation marks, emoji, arrows appended to buttons, or build talk (codes, ports, file names).
8. Motion only answers an action or shows state: ease-out, 150-350 ms, reduced motion respected, never hiding a slow flow.
9. WCAG 2.2 AA, 44 px touch targets, visible focus, no layout shift.
10. Done means: clicked for real with a pointer (nothing invisible covering the page), exercised in a real browser at real sizes, screenshots looked at, the slop list (section 10 of the full page) checked, and you say exactly what you verified.
