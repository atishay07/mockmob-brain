On 18 Oct 2026 at about 1:45 am, the owner said: "I have to explain and give the same feedback again and again, so that should not happen." He asked for a better handoff and prompt format, so context carries forward without loss.

**The format** (in mockmob-next/docs/brain):
- **`OWNER-MASTER-LEDGER.md`:** the one living list of every open owner ask, grouped by surface. Each row has a status (OPEN, BUILT, LIVE-UNCHECKED, DONE, REJECTED, DECIDE). It also holds the "Never again" and "Keep" lists.
- **`NOW.md`:** the current state only: what is live, what is in flight (branch, sha, worktree), the next steps with their chains, and the owner's pending items. Overwrite it at every handoff; git keeps the history.
- **`NEXT-SESSION-PROMPT.md`:** a stable, undated prompt that points to NOW.md, then the master ledger, then the memory.
- **Owner dictation:** save it verbatim in a dated `OWNER-FEEDBACK-<date>.md`, with a ledger and "(confirm)" flags on transcription guesses. Then fold each item into the master ledger the same hour.

**Why:** his asks were scattered over six dated ledgers (W, L, F, N, D, app L), and each dated handoff restated them, so agents lost items. His dictated messages mix chatter with important asks.

**How to apply:**
- Every session reads NOW.md, then the master ledger, before planning.
- Every session updates both before it ends.
- DONE means verified live or on a walked APK; merged is not done.
